## 唯一执行器

`scripts/migrate_db.py` 是**唯一**迁移执行器：发现 sql/ 下版本文件、按版本序应用缺失项、每条迁移与其 `schema_migrations` 记账行**同事务提交**、已应用文件 sha256 字节校验（改字节即拒绝运行）。CI、部署脚本与本地开发都调它——历史上六份手写文件清单已经漂移过（CI 只跑 001+002、部署 glob 指向已搬走的目录），所以现在禁止任何消费方自持清单。

| 命令 | 用途 |
|------|------|
| `python3 scripts/migrate_db.py` | 应用缺失迁移 |
| `--status` | 数据库已记录的版本 |
| `--dry-run` | 下次运行会应用什么 |
| `--baseline` | 采纳 initdb.d 已建好的新卷 |
| `--reset-schema` | 仅 loopback 的开发重置 |

## 守卫与基线

`scripts/check_migrations.py`（CI 硬门禁）守：命名 `NNN_snake_case.sql`、版本链无缺口、新迁移幂等且非破坏、基线不可变（`scripts/migrations_baseline.json`）。已发布迁移用 `--write-missing` 钉住：只新增条目不改旧条目；被钉文件永久豁免内容规则，改它必须同 PR 改基线。

## 边界规则

- **建库是 provisioning 不是迁移**：应用角色无 CREATEDB，执行器只探测并打印超户命令；
- **行尾钉 LF**（.gitattributes）：钉的是提交字节，CRLF 工作副本会与基线和 Linux runner 不一致；
- 禁止在工作流/脚本里写 `psql -f sql/…`；新迁移走 `/create-migration` 技能清单。
