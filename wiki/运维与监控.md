## Prometheus 指标

两层聚合：

- **宿主 /metrics**：PromExporter 基础指标 + `PayAuthMetrics::toPrometheus()`；
- **插件 auth 指标**：四个 atomic 计数器导出 `pay_auth_missing_key_total` / `pay_auth_invalid_key_total` / `pay_auth_scope_denied_total` / `pay_auth_not_configured_total`（PayAuthMetrics.cc:50-53），另有 base/metrics/auth 与 .prom 两个 API Key 保护的路由。

监控栈：docker-compose monitoring profile（Prometheus + Grafana），`examples/pay-server/deploy/` 含 Prometheus 配置、告警规则 alerts.yml、Grafana 面板。

宿主 `/healthz`、`/readyz`（HealthCheckController.h）：3 次失败阈值 + 滞回，避免单次抖动触发 ECS 滚回。部署流水线生产 leg 用 /readyz 30 次健康检查决定是否回滚。

## 六 tier 日志分级

TECH_SPECS「日志分级规范」：

| 级别 | 用途 |
|------|------|
| LOG_FATAL | 仅进程退出级失败（罕见） |
| LOG_ERROR | 需要人介入的错误 |
| LOG_WARN | fire-and-forget 助手失败（台账/幂等快照） |
| LOG_INFO | 仅生命周期/里程碑事件 |
| LOG_DEBUG | 每请求流程步骤 |
| LOG_TRACE | 原始 body/签名内部材料 |

每请求步骤用 INFO 是常见错误（应为 DEBUG）；调试代码提交前必须移除或降为 LOG_DEBUG。
